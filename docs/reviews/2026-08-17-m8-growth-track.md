## 2. 切片划分（G1–G4）

### G1 IP 执行（软著 + 商标）
我方交付 = 申请材料包与指引，提交动作归用户（或其代理）：
软著——登记材料生成（源程序文档按中国版权保护中心页数规则自动抽取、软件说明书从
既有文档拼装）+ 申请流程指引；商标——先行检索报告（中国 9/42 类与美国对应类别的
近似查询结果快照）+ 申请要素包（名称/图样/商品服务项列表）。
**验收**：材料包完整可直接提交（用户确认无缺项）；检索报告含结论与依据快照。

### G2 文档体系（全量对齐 + 生成器门控）
全量文档事实对齐审计：以「每个数字/命令/路径可溯源到当前代码或实测」为标准列漂移
清单并逐一修复（用户原话「没有漂移/过时」= 硬标准）；代码级文档生成器（CLI 参考文档
自 --help/子命令面生成、配置参考自 ce.toml 模式生成）+ 漂移门入 CI（复用 regen_tables
先例：生成器重跑与仓内文档比对，漂移即红）；S5 staleDocs 轴自仓门槛收紧评估。
**验收**：审计清单全处置入册；生成器门反事实红（手改生成物→CI 红）；docdup 自检零上报。

### G3 i18n（en 默认 + zh 切换）
用户可见字符串全量普查→查表化：Rust 报告/CLI 层静态表 + `--lang`/`CE_LANG` 选择，
GUI JS 同表机制 + 设置项；判决层 wire 为码与数字、名与文本不过线是既有立场——预期
core 零 i18n 面，开工时普查确认并将该边界写为验收断言。README 默认英文重写（背景/
用途/用法/效果/卖点——用户第 3 条验收标准）+ `README.zh.md` 同步版。
**验收**：两语言查表完备性测试（缺键即红，杜绝混语输出）；README 双语同批入库；
core 零文本断言成立（或分歧如实入册）。

### G4 GitHub 可见度
topics/description/社交预览图、issue + discussion 模板、labels 体系、CONTRIBUTING、
release notes 规范、awesome-list/相关工具清单投递列表（投递动作归用户拍板逐项放行）。
**先决**：P6 转公开完成。模板类文件可在转公开前备好随仓。
**验收**：仓库侧设置全落地截图入册；投递清单与放行记录入册。
