# 计划 v1.0 对抗性评审记录（Opus 攻击视角）

> 2026-08-06 · 评审人：Claude Opus（attack perspective，替代 Codex——当日 Codex 额度耗尽，独立评审未由 Codex 执行）
> 对象：docs/DEVELOPMENT_PLAN.md v1.0（239 行版本）
> 处置：全部 🔴 与主要 🟡 已在 v1.1 修复；逐条处置见文末表。

## 评审结论摘要

- 🔴 A1 §0 "可强制" 定位与 R7 "默认仅 warn" 互斥，缺默认档位演进路线
- 🔴 A2 PreToolUse 拿不到所需输入：(a) 需重放 Edit 落盘语义（隐藏子系统）；(b) Bash/`>>` 绕过路径敞开；(c) §4.3 第一条规则依赖不存在的"任务意图"字段；(d) 无 exclusion 模型（lock 文件必炸）
- 🔴 A3 "NDJSON over stdio" 与 "长驻" 自相矛盾；daemon 生命周期/并发/SQLite 锁/版本 skew/冷启动全部缺失
- 🔴 A4 里程碑倒置：M3 的 Stop/SessionStart 依赖 M4 的四分类与 M5 的棘轮；M5 依赖 M4 不能并行
- 🔴 A5 M4 验收（N=20、accuracy、difftastic 对照）统计效力不足以授权 deny：18/20 的 Wilson 95% CI 下界 ≈70%；指标应为 FPR 上界；样本可玩；difftastic 不识别 moved 无法对照核心维度
- 🔴 A6 延迟预算未分解：3.44s 全量扫描被当作 1s 热路径的正向证据；ce 自身冷启动、IR 体积（token 流 MB 级）、会话累计延迟均无预算
- 🔴 A7 依赖图（三信号 join 支柱、deadcode 前提）没有任何里程碑建设它；readability/deadcode 无归属
- 🔴 A8 R5 循环论证；desloppify 引文删掉了 "yet"；MCP 排 M7 可选而竞品已在位；全计划零工期估算
- 🔴 A9 安全/隐私/卸载空白：二进制分发两套写法互相矛盾且无签名/校验；索引隐私与 secrets 排除未定义；embedding 联网承诺缺失；ce.toml 信任模型缺失；无 eject；fail-open 无可见性
- 🟡 B1 Haskell 在 M0–M3 不承重但 M0 付掉全部双语言成本；契约内容不应在需求已知前冻结
- 🟡 B2 验收标准可玩性：交叉核对 fixtures 自选、首发语言集中 Haskell/Markdown 无对照物、召回无配对精度、"权重和=1" 测不到 fuck-u-code 实际那类 bug（死字段），应为敏感性测试
- 🟡 B3 更优替代未评估：混合强制点（PreToolUse 廉价 + PostToolUse/Stop 深判）；复用 jscpd 引擎的否决理由未记录；四分类缺 git -M/-C 行级 fallback 阶梯
- 🟡 B4 guard 默认档位 warn 会向上下文持续注入报告——anti-bloat 工具自己成为上下文熵源，无 token 预算
- 🟡 B5 棘轮对连续型指标与离散型违规语义未区分；与 --fail-under 合成语义未定义
- 🟡 B6 License 是 M0 前置条件（复用 MIT 代码、公开仓库分发），不能标"不阻塞 M0"
- 🔵 C1 ρ=0.94 措辞过强（相关非因果 + 规模效应）；C2 文档预算 550 行违反自家棘轮精神、§8.4 交叉引用悬空；C3 GHC 9.14 生态可解性未核实；C4 二进制体量乐观锚点（hlint 18.99MB）

总判决：第一死因 M3 无法收敛；第二死因 M4 过验收但真实误报毁信任；第三死因双语言成本先于价值支付。
