# T1/T2 clone detection — winnowing fingerprint index

[index](../methodology.md) · [→ 02 T3 near-miss clones — Tree Edit Distance (TSED)](02-t3-near-miss-clones-tree-edit-distance-tsed.md)

The hot path is fixed by ADR-005: normalized token stream → winnowing/Rabin-Karp fingerprints over a SQLite inverted index, with the Schleimer et al. SIGMOD'03 no-miss lower bound as the correctness contract; the cold path (AST structural fingerprint → TSED, T3) is separate ([DEVELOPMENT_PLAN.md:198-202](../../DEVELOPMENT_PLAN.md#L198)). The whole computation is deterministic: the same bytes and the same `Params` produce the same fingerprint rows, the same anchor set, and the same blocks in the same order.

Stages: parse → normalize to tokens → hash tokens → k-gram rolling hash → per-window minimum selection → index → anchor pairing → exact bidirectional extension → the coverage rule with its diversity floor, judged in the core.

### 1. Token normalization alphabet

Tokenization walks the tree-sitter tree and emits one `Token { hash, start_line, end_line }` per **leaf** ([tokens.rs:36-41](../../../cli/src/dedup/tokens.rs#L36), [tokens.rs:69-113](../../../cli/src/dedup/tokens.rs#L69)). The walk uses `ast::children`, which enumerates `child_count()` and therefore includes **anonymous** nodes ([ast.rs:57-59](../../../cli/src/scan/ast.rs#L57)) — punctuation and keywords are part of the alphabet, not discarded. Comment nodes are skipped as whole subtrees ([tokens.rs:120-122](../../../cli/src/dedup/tokens.rs#L120)).

Each leaf is classified into exactly three classes ([tokens.rs:173-181](../../../cli/src/dedup/tokens.rs#L173)):

| Class | Predicate | Bytes hashed |
|---|---|---|
| `Id` | `kind.ends_with("identifier")` ([tokens.rs:174](../../../cli/src/dedup/tokens.rs#L174)) | `ID_MARK = b"\x01ID"` ([tokens.rs:43](../../../cli/src/dedup/tokens.rs#L43)) |
| `Lit` | `is_literal(kind, spec)` ([tokens.rs:177](../../../cli/src/dedup/tokens.rs#L177)) | `LIT_MARK = b"\x02LIT"` ([tokens.rs:44](../../../cli/src/dedup/tokens.rs#L44)) |
| `Text` | otherwise ([tokens.rs:180](../../../cli/src/dedup/tokens.rs#L180)) | the node's **kind text**, `kind.as_bytes()` ([tokens.rs:128](../../../cli/src/dedup/tokens.rs#L128)) |

Collapsing identifiers and literals to two fixed marks while keeping every other node's kind text verbatim is exactly the T2 equivalence: renamed variables and changed constants are clones, changed syntax is not. The `\x01` / `\x02` prefixes keep the marks outside the space of real grammar kind strings, so no kind text can alias them.

`is_literal` sees leaf kinds and the named descendants of a string-shaped literal (composite kinds such as Go `composite_literal` never reach it, because `tokenize` recurses on any node with children first — [tokens.rs:83-95](../../../cli/src/dedup/tokens.rs#L83), [tokens.rs:187-190](../../../cli/src/dedup/tokens.rs#L187)). It accepts ([tokens.rs:191-208](../../../cli/src/dedup/tokens.rs#L191)):

- `kind.ends_with("literal")`;
- `kind ∈ {"integer", "float", "number", "escape_sequence", "raw_string_delimiter", "literal_suffix"}`;
- `kind.contains("string")` **and** `kind` ends with one of `content` / `fragment` / `start` / `end`;
- `kind ∈ spec.literal_delims` — the per-language anonymous delimiter tokens.

`literal_delims` is per-language because a delimiter in one grammar is an operator in another: TypeScript `["\"", "'", "`"]` ([TypeScript.hs:80](../../../core/app/CE/Lang/TypeScript.hs#L80)), Go `["\"", "`"]` — `'` is the rune delimiter but `rune_literal` lexes as one token ([Go.hs:64-65](../../../core/app/CE/Lang/Go.hs#L64)), Rust `["\""]` only, because `'` is the lifetime/label tick and classifying it as `LIT` made every `&'a str` signature a false clone driver ([Rust.hs:58-60](../../../core/app/CE/Lang/Rust.hs#L58)), Python `[]` because quotes surface as named `string_start` / `string_end` kinds ([Python.hs:79-80](../../../core/app/CE/Lang/Python.hs#L79)), Haskell `[]` because a string lexes as one `string` leaf with the quotes inside ([Haskell.hs:102-104](../../../core/app/CE/Lang/Haskell.hs#L102)). The v2.30 grammars follow the same reading: C and C++ share one table — `"`, `'`, `character` and the raw-string opener `R"` — with a string, char or user-defined literal node read whole as one `LIT` ([C.hs:126](../../../core/app/CE/Lang/C.hs#L126), [tokens.rs:155-171](../../../cli/src/dedup/tokens.rs#L155)); Java `"` and the text-block `"""` ([Java.hs:111](../../../core/app/CE/Lang/Java.hs#L111)); Lua `"`, `'`, `[[` and `]]` ([Lua.hs:94](../../../core/app/CE/Lang/Lua.hs#L94)); R the named `string_open` / `string_close` kinds ([R.hs:96](../../../core/app/CE/Lang/R.hs#L96)); HTML takes Markdown's empty table and is never tokenized ([Markdown.hs:12-15](../../../core/app/CE/Lang/Markdown.hs#L12), [Html.hs:12-16](../../../core/app/CE/Lang/Html.hs#L12)).

Two deliberate stances, documented at the module head ([tokens.rs:7-9](../../../cli/src/dedup/tokens.rs#L7)): booleans and `None` are **not** collapsed to `LIT` (their identity is usually semantic, unlike numbers and strings), and Go `blank_identifier` normalizes to `ID` like any identifier.

Multi-piece literals collapse to one token, but **only within the same parent literal node** — `lit_parent` is the parent node id, and a piece whose parent matches merely extends the previous token's `end_line` ([tokens.rs:97-105](../../../cli/src/dedup/tokens.rs#L97), [tokens.rs:137-141](../../../cli/src/dedup/tokens.rs#L137)). Merging by lexical adjacency instead swallowed whole statements (a Python attribute docstring after a string assignment vanished into the previous `LIT`'s span). A string-shaped literal node — a string, char or user-defined literal none of whose named descendants is anything but a literal piece — is one token before any piece is visited ([tokens.rs:78-95](../../../cli/src/dedup/tokens.rs#L78), [tokens.rs:155-171](../../../cli/src/dedup/tokens.rs#L155)): a C++ raw, delimited or prefixed string and a user-defined literal weigh what a plain string weighs (plan v2.30 step 5b; a raw string used to weigh five), while a literal holding code — a Java `\{x}` interpolation — fails the test and keeps the piece rule.

Token hashing is FNV-1a over those bytes: `h = 0xcbf29ce484222325`, then per byte `h ^= b; h = h * 0x100000001b3` in wrapping u64 arithmetic ([tokens.rs:212-214,231-237](../../../cli/src/dedup/tokens.rs#L212)). It is dependency-free and stable across runs, which is required because the index persists.

**The import family gives no token** (v2.35). Name plumbing is skipped as a whole subtree, the standing treatment of a comment ([tokens.rs:115-122](../../../cli/src/dedup/tokens.rs#L115)): the body-less declarations the reference graph reads as a module reference or identity — `import`, `#include`, `use`, `extern crate`, the package clause, the Haskell module header `module X (…) where` with its export list (the module's identity, as the package clause is), the module mount `mod x;` and the re-export `export … from "m"` — and the load statements, a statement that is nothing but loads bound to names (Lua `local x = require("m")`, R `library(x)`, CommonJS `const x = require("m")`, Python `m = importlib.import_module("x")`; [loads.rs:1-12](../../../cli/src/scan/loads.rs#L1)). Both are the definition package's tables, per language: `[scan] import_kinds` entries are `'<kind>'`, `'<kind> <field>'` (a named node of that kind with a child under that field) or `'<kind> !<field>'` (with none) — Rust `'mod_item !body'`, TypeScript `'export_statement source'`, Haskell `'header'` ([Rust.hs:79](../../../core/app/CE/Lang/Rust.hs#L79), [TypeScript.hs:98](../../../core/app/CE/Lang/TypeScript.hs#L98), [Haskell.hs:129](../../../core/app/CE/Lang/Haskell.hs#L129), [loads.rs:20-36](../../../cli/src/scan/loads.rs#L20)) — and `[scan] loads` names the statement lists and the statement shapes whose every end is a call the call-site table opens a site for ([Lua.hs:122](../../../core/app/CE/Lang/Lua.hs#L122), [R.hs:113](../../../core/app/CE/Lang/R.hs#L113), [loads.rs:38-45](../../../cli/src/scan/loads.rs#L38)). What stays code, because it is no module reference: a Rust `mod x { … }` with its body, `export const` / `export default` / `export { a, b };`, C++ `using` declarations, Java annotations, Python `__all__` (these name no module). The external precedent is Java's: PMD CPD's Java lexer discards package and import statements ([JavaCpdLexer.java:80-81, 113-116](https://github.com/pmd/pmd/blob/4a1d37d3eb785695084393fcc7315b0aca123809/pmd-java/src/main/java/net/sourceforge/pmd/lang/java/cpd/JavaCpdLexer.java)) and SonarQube's Java statement chunker ignores them ([JavaStatementBuilder.java:33-34](https://github.com/SonarSource/sonarqube/blob/ad7389bfac6439cb88688a5e3931b8a8e78cb613/sonar-duplications/src/main/java/org/sonar/duplications/java/JavaStatementBuilder.java)), while PMD's C# option `--ignore-usings` defaults the other way; for the other languages the rule is this repository's own stance. A block whose tokens outside the import family number fewer than `t` is below the report threshold by definition, so a run made mostly of import lines is no longer reported. The limit: what stands above a file's first include or load and is no declaration of the family stays code and can join a run with the code below it — C++ preprocessor lines (an include guard, configuration macros: 95th percentile 10 tokens above the first `#include` over the corpora, at most 27), a compiled-Teal shim (one generated line of 60 to 200 tokens above luarocks' first `require`), a Haskell `LANGUAGE` pragma (one token). Measured in v2.35: no reported block on the self tree and the corpora arises from a head that holds no statement; on the duplicate-write replays one intercept does — on this repository's history a 49-token Haskell run reaches 50 with its pragma (1 of 268 rows) — and on the six per-language chains none (luarocks' 55 lane-only rows lifted by a head are the shim itself, statements shared verbatim).

Normalization semantics are versioned: <!--ce:ver:tokenizer_rev#digits-->`TOKENIZER_REV = 5`<!--/ce--> ([tokens.rs:33](../../../cli/src/dedup/tokens.rs#L33)) is stored in the index meta table and a mismatch clears every parser-derived table while the trend history stays — stamped with the revision that measured it and remeasured before reuse ([parser.rs:56](../../../cli/src/dedup/schema/parser.rs#L56), [mod.rs:4-8](../../../cli/src/trend/mod.rs#L4)) — so fingerprints from an older tokenizer can never mix with new ones ([schema.rs:112-122](../../../cli/src/dedup/schema.rs#L112), [schema.rs:181-203](../../../cli/src/dedup/schema.rs#L181)).

Languages that do not fingerprint (`Lang::fingerprints() == false` — a grammar-less language such as Markdown or plain text — the scan-only arm never reaches the index at all ([lang.rs:176-178](../../../cli/src/scan/lang.rs#L176)) — and HTML, whose grammar feeds its sections, sites and page text but whose leaves carry no identifiers, so any two pages would hash into one clone pair; [lang.rs:243-245](../../../cli/src/scan/lang.rs#L243)) get no token stream and therefore **zero** fingerprint rows ([index.rs:176-193](../../../cli/src/dedup/index.rs#L176)). Fingerprints exist for Python, TypeScript, TSX, Rust, Go, Haskell, C, C++, Java, Lua and R.

### 2. k-gram rolling hash

Winnowing consumes only the `hash` field of the token stream ([index.rs:181-182](../../../cli/src/dedup/index.rs#L181)). Let `t[0..n]` be that sequence and `k = p.kgram`.

- `BASE = 1_000_003` ([winnow.rs:17](../../../cli/src/dedup/winnow.rs#L17)), all arithmetic wrapping u64.
- If `n < k`, the hash list is empty and the file contributes no fingerprints ([winnow.rs:29-31](../../../cli/src/dedup/winnow.rs#L29)).
- `top = BASE^(k-1)` (wrapping) ([winnow.rs:32](../../../cli/src/dedup/winnow.rs#L32)).
- Seed: `h_0 = ((t[0]*BASE + t[1])*BASE + … )*BASE + t[k-1]`, i.e. `h = h*BASE + t[j]` for `j` in `[0, k)` ([winnow.rs:34-38](../../../cli/src/dedup/winnow.rs#L34)).
- Roll, for `i` in `[k, n)`: `h = (h - t[i-k]*top)*BASE + t[i]` ([winnow.rs:39-45](../../../cli/src/dedup/winnow.rs#L39)).

This yields exactly `n - k + 1` k-gram hashes ([winnow.rs:33](../../../cli/src/dedup/winnow.rs#L33)). It is the standard Rabin-Karp update; the same function is `pub(crate)` and reused by docdup's word shingles so the offline oracle and the product filter cannot fork into two Rabin-Karps ([winnow.rs:19-24](../../../cli/src/dedup/winnow.rs#L19)).

### 3. Window minimum selection and the no-miss guarantee

Over the k-gram hash array `g[0..m]` with `w = p.window`:

- Window count: `windows = max(m - (w - 1), 1)` ([winnow.rs:64](../../../cli/src/dedup/winnow.rs#L64)). The `.max(1)` means a stream with fewer than `w` k-grams still gets one window, truncated by `end = min(start + w, m)` ([winnow.rs:66](../../../cli/src/dedup/winnow.rs#L66)).
- Within window `[w_i, end)` take the minimum, scanning left to right with `<=` so **ties resolve to the rightmost** occurrence ([winnow.rs:67-72](../../../cli/src/dedup/winnow.rs#L67)).
- A position is recorded **once**: if the chosen `min_idx` equals `last_recorded`, nothing is pushed ([winnow.rs:63](../../../cli/src/dedup/winnow.rs#L63), [winnow.rs:73-79](../../../cli/src/dedup/winnow.rs#L73)). Consecutive windows sharing a minimum therefore contribute one fingerprint, not `w`.

A selected `Fingerprint { hash, start }` covers tokens `[start, start + kgram)` ([winnow.rs:10-15](../../../cli/src/dedup/winnow.rs#L10)).

The two thresholds ([mod.rs:274-277](../../../cli/src/dedup/mod.rs#L274), [winnow.rs:4-6](../../../cli/src/dedup/winnow.rs#L4)):

- **Guarantee threshold** `t = window + kgram - 1` ([mod.rs:284-292](../../../cli/src/dedup/mod.rs#L284)). Any common substring of at least `t` normalized tokens contains at least `t - k + 1 = w` consecutive k-grams — one complete window — and since selection depends only on the contents of that window, both copies select the same minimum. Hence **≥ 1 shared fingerprint, always**. The positional dedup does not weaken this: it suppresses only a re-record of a position already emitted.
- **Noise threshold** `k = kgram`: no match shorter than `kgram` tokens can ever be reported, because a fingerprint is a whole k-gram.

Defaults: `kgram = 25`, `window = 26`, so `t = 26 + 25 - 1 = 50` tokens — chosen to align with the jscpd min-tokens default ([mod.rs:292-297](../../../cli/src/dedup/mod.rs#L292)). The report filter defaults to exactly `p.guarantee()` ([mod.rs:155-158](../../../cli/src/dedup/mod.rs#L155)); lowering it with `--min-tokens` is a calibration mode, and detection below `t` is opportunistic rather than guaranteed ([mod.rs:34-37](../../../cli/src/dedup/mod.rs#L34)).

### 4. The inverted index

Fingerprints land in `fingerprints(hash, file_id, start_tok, start_line, end_line)` with `idx_fp_hash` and `idx_fp_file`, cascade-deleted from `files` ([schema.rs:89-97](../../../cli/src/dedup/schema.rs#L89)). Line mapping at insert time is `start_line = toks[f.start].start_line` and `end_line = toks[f.start + p.kgram - 1].end_line` ([index.rs:430-431](../../../cli/src/dedup/index.rs#L430)) — the span of the k-gram, not of one token.

Invalidation is content-hash gated per file: `content_hash = fnv1a(src)`, and a match short-circuits the refresh entirely ([index.rs:140](../../../cli/src/dedup/index.rs#L140), [index.rs:156](../../../cli/src/dedup/index.rs#L156)); a change deletes and reinserts only that file's rows in one transaction ([index.rs:183-216](../../../cli/src/dedup/index.rs#L183)). The whole database is keyed by <!--ce:ver:schema.index#digits-->`SCHEMA_VERSION = 17`<!--/ce--> ([schema.rs:62](../../../cli/src/dedup/schema.rs#L62)) plus the meta tuple `(kgram, window, tokenizer_rev, graph_rev, struct_rev, docdup_rev, similar_rev)` ([schema.rs:190-200](../../../cli/src/dedup/schema.rs#L190)); a mismatch of the tokenizer revision or of the definition package's digest (`tables_digest`, read off the core's package since v2.35) clears every measured row and keeps the trend history, any other mismatch wipes and rebuilds, so neither a parameter change nor a core whose package moved can silently reuse stale fingerprints. The result cache's slot key is seeded with the same package digest and the hot-group cap.

Instance queries sort their rows before returning ([index.rs:339](../../../cli/src/dedup/index.rs#L339), [index.rs:357](../../../cli/src/dedup/index.rs#L357)), so downstream pairing sees a fixed order regardless of SQLite's row order.

### 5. Anchor pairing

Shared fingerprints are **candidate anchors only** — nothing is reported on a hash match alone ([pairs.rs:1-7](../../../cli/src/dedup/pairs.rs#L1)). Instances are grouped by `hash` in a `BTreeMap` and only groups of size > 1 are visited ([anchors.rs:34-38](../../../cli/src/dedup/pairs/anchors.rs#L34)):

- Group size `n <= hotCap` → full pairwise, `C(n,2)` pairs ([anchors.rs:45-51](../../../cli/src/dedup/pairs/anchors.rs#L45)).
- Group size `n > hotCap` → sort by `(file, start_tok)` and emit the `n-1` adjacent pairs, counting one `Chained` event ([anchors.rs:39-44](../../../cli/src/dedup/pairs/anchors.rs#L39)).

`hotCap = 64` ([Cost.hs:39-40](../../../core/app/CE/Dedup/Cost.hs#L39)), read off the definition package since plan v2.33 W3 ([anchors.rs:18-20](../../../cli/src/dedup/pairs/anchors.rs#L18)) — the same cap the T3 sources and the docdup coarse filter chain by. Chaining rather than skipping is load-bearing: skipping hot groups made detection fall to **zero as duplication rose** — 65 identical files produced 0 blocks — while the chain keeps every instance in at least one verified pair at linear cost ([anchors.rs:10-17](../../../cli/src/dedup/pairs/anchors.rs#L10)). One grouping walk serves both the T1/T2 extension pass and the S3 candidate source, so the two cannot disagree about which anchors exist ([anchors.rs:29-32](../../../cli/src/dedup/pairs/anchors.rs#L29)).

### 6. Anchor extension (verification)

Each pair is normalized to `(a, b)` ordered by `(file, start_tok)` ([pairs.rs:206-210](../../../cli/src/dedup/pairs.rs#L206)), then verified against the two live token streams. A stored offset past the end of the live stream means the file changed after the index refresh: the anchor is skipped and counted in `stale_skipped`, never allowed to index out of bounds ([pairs.rs:217-221](../../../cli/src/dedup/pairs.rs#L217), [pairs.rs:54-57](../../../cli/src/dedup/pairs.rs#L54)).

`extend` computes the maximal **exact** common run around the anchor on token hashes ([pairs.rs:237-247](../../../cli/src/dedup/pairs.rs#L237)):

1. Backward: while `a0 > 0 && b0 > 0 && sa[a0-1].hash == sb[b0-1].hash`, decrement both ([pairs.rs:244-248](../../../cli/src/dedup/pairs.rs#L244)).
2. Forward: `cap = b0 - a0` when both sides are the same stream, else `usize::MAX` ([pairs.rs:250](../../../cli/src/dedup/pairs.rs#L250)); grow `len` while `a0+len < |sa|`, `b0+len < |sb|`, `len < cap`, and `sa[a0+len].hash == sb[b0+len].hash` ([pairs.rs:251-257](../../../cli/src/dedup/pairs.rs#L251)).
3. Return `(a0, b0, len)` when `len > 0` ([pairs.rs:258](../../../cli/src/dedup/pairs.rs#L258)).

The same-stream cap keeps the two ranges disjoint — periodic code reports adjacent segments instead of one self-overlapping range ([pairs.rs:232-236](../../../cli/src/dedup/pairs.rs#L232)).

Runs are then sorted into two sinks ([pairs.rs:223-229](../../../cli/src/dedup/pairs.rs#L223)): `len >= t` is a reportable run; `near_floor <= len < t` goes to the near-miss sink, which with the floor at `kgram` is exactly `25 <= len < 50` and is the T3 candidate source S1 ([pairs.rs:176-181](../../../cli/src/dedup/pairs.rs#L176)). `near_floor = usize::MAX` disables it ([pairs.rs:91-93](../../../cli/src/dedup/pairs.rs#L91)).

Reportable runs are mapped to lines via the run's endpoint tokens: `a_start = sa[a0].start_line`, `a_end = sa[a0+len-1].end_line` ([pairs.rs:266-278](../../../cli/src/dedup/pairs.rs#L266)). A span runs from a block's first token to its last, and no head declaration carries one. A run continues across the import family's lines, so the printed span may name import lines one side lacks or that differ; the extent law counts them as it counts a comment line inside a block. The self tree's worked example is `core/test/AuditProps.hs:3-35` ↔ `SplitProps.hs:3-36` (51 tokens): the `LANGUAGE` pragma on line 3 is a token, the module header and the imports below it carry none, so the run starts at the pragma and continues into the battery; with the pragma's lines blank the same pair is reported from the battery's first line (`19-35` ↔ `17-36`, 50 tokens).

Which verified runs are reported is the core's **coverage rule C_t** (`cover/1`, [Rule.hs:1-27](../../../core/app/CE/Dedup/Cover/Rule.hs#L1)); this side sends every verified run as token offsets with the run's two filters and maps the classes back ([pairs.rs:127-135](../../../cli/src/dedup/pairs.rs#L127), [cover.rs:46-71](../../../cli/src/dedup/pairs/cover.rs#L46)). Per file pair: the runs split into D (`distinct >= d`) then Lo; inside a class, `len` descending, then `a0`, `b0`; one cover of covered tokens per file — one shared cover when the two files are one; a run is kept iff `max(na, nb) >= t`, where `na` and `nb` are its tokens outside the cover on each side, and a kept run joins the cover on both sides; Lo is folded after D against the cover D left ([Rule.hs:78-96](../../../core/app/CE/Dedup/Cover/Rule.hs#L78)). A kept D run is reported, a kept Lo run suppressed, the rest dropped. So every run of a pair is kept or has fewer than `t` tokens outside the cover on each side, and every kept run had `t` tokens of its own when it joined. Periodic content, which yields one maximal run per offset, keeps one run per stretch of new tokens. Before v2.35 the measuring side compared LINE spans instead (`dominant`): a shorter run whose lines sat inside a longer one vanished even when most of its tokens were its own, and a low-diversity run could hide a diverse one; that pass is deleted. A request is split between file pairs under `cover_rows` = 262144 rows, and one pair past it is refused by name ([Cost.hs:42-51](../../../core/app/CE/Dedup/Cost.hs#L42)). That every k-way group keeps a member in each region it had is a measured fact, not a theorem: the coverage rule against the import family alone lost no group member region on any of the 17 trees that answer (v2.35 phase 3A); against main's output, every region no reported block covers any more (480 on 9 trees) belonged to a block that reached 50 tokens only with import, load or module-header tokens.

### 7. The `min_distinct` low-diversity floor

`distinct` is the cardinality of the set of token hashes inside the verified run: `|{ sa[i].hash : i ∈ [a0, a0+len) }|` ([pairs.rs:261-264](../../../cli/src/dedup/pairs.rs#L261)). It is the literal-degeneracy signal: a data-row match such as a `LIT: (LIT, ...),` table has a tiny alphabet, while a real code clone is diverse ([pairs.rs:39-44](../../../cli/src/dedup/pairs.rs#L39)).

`minDistinct = 7` ([Cost.hs:30-31](../../../core/app/CE/Dedup/Cost.hs#L30)), read off the definition package since plan v2.33 W3 ([pairs.rs:85-87](../../../cli/src/dedup/pairs.rs#L85)). The calibration: across the fixture corpus plus cobra and requests, the arbitrated data-row false positives (status_codes rows, locale key sections, pygments style dicts) measured `distinct <= 6`, while arbitrated true clones measured `distinct >= 7` ([pairs.rs:68-73](../../../cli/src/dedup/pairs.rs#L68)). The same comment records that one 16-outlier false positive survives the floor — it buys precision, not purity.

The floor is the coverage rule's first split: a run below it can only be kept after every diverse run of its pair, a kept one is suppressed, and their number is reported as `low_diversity_suppressed` rather than discarded silently ([pairs.rs:153-158](../../../cli/src/dedup/pairs.rs#L153), [pairs.rs:58-60](../../../cli/src/dedup/pairs.rs#L58)); `--min-distinct` overrides it ([mod.rs:44](../../../cli/src/dedup/mod.rs#L44), [mod.rs:157](../../../cli/src/dedup/mod.rs#L157)) — on the `--check` road only in the tightening direction: `--min-tokens` above 50 and `--min-distinct 0` are refused by name before any measurement or core contact, and `--min-distinct` above 7 before any measurement, once the floor is read off the definition package ([budget.rs:33](../../../cli/src/dedup/budget.rs#L33)), so the ratchet always judges at the calibrated operating point or a stricter one. Note that the floor filters blocks only — the near-miss sink keeps its own honest `distinct` but is not filtered by it ([pairs.rs:176-181](../../../cli/src/dedup/pairs.rs#L176)).

### 8. What the report carries
