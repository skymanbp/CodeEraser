# FPR discipline and the guard tier ladder

[index](../methodology.md) · [← 10 Score trajectory — the trend slope verdict](10-score-trajectory-the-trend-slope-verdict.md) · [→ 12 Deterministic erase — the safety predicate](12-deterministic-erase-the-safety-predicate.md)

### The thesis: a deterministic gate over a nondeterministic writer

The guard sits on `PreToolUse` for `Write|Edit` ([guard.rs:36-41](../../../cli/src/guard.rs#L36), [guard.rs:51-59](../../../cli/src/guard.rs#L51)) and answers one question per pending write with exact arithmetic, never with a model. Four rule classes fire there: a T1/T2 duplicate-write probe against the fingerprint index, a hard-budget breach computed locally ([guard.rs:102-121](../../../cli/src/guard.rs#L102)), and two classes that speak only at their own tiers: the tombstone-residue class at `[tombstone] tier` and budget, and the intra-function dead-code class at `[flow] tier` and only for a language the flow precision gate admitted ([guard.rs:124-147](../../../cli/src/guard.rs#L124)).

Since the K-round root fix the duplicate-write rule judges **novel** duplication only: the probe's matches are subtracted by the matches the REPLACED content already carried — Write replaces the on-disk file, Edit replaces `old_string` — so a full rewrite of a file carrying budgeted blocks, or an edit inside one, is carried duplication and stays silent, while an introduction still denies ([probe.rs:71-102](../../../cli/src/guard/probe.rs#L71)). The subtraction counts copies (release 1.10.0): the probe reports how many disjoint copies of each source region the text holds, and the replaced content carries as many as it held — a second copy written beside the one a file already carried is novel and denies, where before it rode the first copy's allowance. The rule and its three properties are booklet 09's ([probe.rs:133](../../../cli/src/guard/probe.rs#L133)); the standing replay's reading under it is in [FPR-REPLAY.md](../../FPR-REPLAY.md). The replaced content is read once per hook call. A split to a NEW file has no replaced content and still denies; its reason teaches the ordering that passes — trim the source first, because candidate verification reads the current tree ([Text/Guard.hs:14](../../../core/app/CE/Text/Guard.hs#L14)). The baseline probe runs only when the first probe matched, and a degraded baseline subtracts nothing: allowance never rides an unanswered question. An envelope the hook cannot read as JSON, or one that names no working directory, is not judged and is written to the feed as a degraded line naming why, instead of passing in silence.

Three further facts decide what a match is (v2.35). A **relocation** passes: when the probe matched, the hook counts each matched run in HEAD and in the tree the write leaves — every path `git diff --name-status HEAD` names, untracked files, and the target — and the core's `relocate/1` stage, a stage of this class rather than a family, judges `occNow ≤ occHead`; a write all of whose matches are relocations is not refused, so moving a function whose source was removed first no longer refuses while it has other surviving twins, and the wall it mirrors, `ce dedup --check`, saw no new block either ([relocate.rs:52-71](../../../cli/src/guard/relocate.rs#L52)). Without git, or past its read caps, there is no credit and the reason is on the probe line. Every **candidate** is matched by its current fingerprints: the index only selects candidate files, so a candidate edited since the last refresh is still matched where its code now sits ([dedup/probe.rs](../../../cli/src/dedup/probe.rs)). And the session's **own writes** are candidates: after a write lands, the PostToolUse leg asks a running daemon to re-measure that one file in the shared index — only a file of a fingerprinting language, in scope and the project's own, only when the index exists and is current; it never builds an index or starts a daemon, and a failure is a degraded stamp on the `settled` line ([settle.rs:53-68](../../../cli/src/guard/settle.rs#L53), [reindex.rs:37](../../../cli/src/daemon/server/reindex.rs#L37)). Every sentence the four rule classes and the armed graded zone speak lives in one catalogue, English and Chinese side by side ([Text/Guard.hs:1-23](../../../core/app/CE/Text/Guard.hs#L1)) — in the core since v2.32 step 5: the hook sends the rules that fired as integer rows and its strings as references, over the daemon's held link, and binds the one sentence it gets back ([speech.rs:1-13](../../../cli/src/guard/speech.rs#L1)). They were gathered because they had not been: the templates sat inline at six call sites across two files, nothing asked them as a set, and this face answered `CE_LANG=zh` in English while the Stop audit had answered in Chinese since M8-G3b.

Determinism is bought by *replaying the write* rather than estimating it, once per hook call: `applied::apply` works the write out and hands the same text to the size classes, the probe, the tombstone leg and the flow leg ([applied.rs:82-113](../../../cli/src/guard/applied.rs#L82)). `Write` returns its own payload, while `Edit` applies its payload to the on-disk file: CRLF-normalized, and a non-`replace_all` edit requires a **unique** match. An Edit that cannot apply leaves the rules silent and says why on the probe line, in one of four values: `absent` (the target does not exist; the tool fails on its own), `unreadable` (any other I/O failure, a degraded stamp), `no_match` or `ambiguous` ([applied.rs:55-79](../../../cli/src/guard/applied.rs#L55)). The gate never judges a write that will not land.

The same discipline is applied to the *policy* value, not only the measurement. `Guard::tier` is total by construction: an unrecognized `[guard] mode` resolves to an `observe (ce.toml ERROR: unknown guard mode …)` string rather than being passed through verbatim ([tier.rs:56-65](../../../cli/src/config/tier.rs#L56)), because a pass-through typo previously disarmed every enforcement path while `SessionStart` still printed the mode as armed ([tier.rs:47-55](../../../cli/src/config/tier.rs#L47)). A load failure renders through the same single throat, `tier_of` ([tier.rs:94-102](../../../cli/src/config/tier.rs#L94)), so a broken config can never print byte-identically to a deliberate `observe`.

Two honesty boundaries bound the thesis, and both are written into the plan:

- `PreToolUse` is a **behavior-shaping layer, not a security boundary** — an agent can bypass it with `Bash: echo >>` or `sed -i`; the backstop is the `Stop` audit over `git diff` (write-tool agnostic) plus the CI gate ([DEVELOPMENT_PLAN.md:92-94](../../DEVELOPMENT_PLAN.md#L92)).
- The hook is **fail-open**: any internal failure allows the edit, and the degraded run lands in the observe feed ([guard.rs:5-6](../../../cli/src/guard.rs#L5)); a probe that cannot reach the daemon returns `None`, which is logged as `degraded` rather than treated as "no duplicates" ([probe.rs:186-204](../../../cli/src/guard/probe.rs#L186), [probe.rs:246](../../../cli/src/guard/probe.rs#L246)).

### The tier ladder

Four tiers, and nothing else is a tier: `TIERS = ["observe", "warn", "ask", "deny"]` ([tier.rs:40](../../../cli/src/config/tier.rs#L40)). They map onto Claude Code's decision JSON at one emission point ([guard.rs:225-242](../../../cli/src/guard.rs#L225)):

| tier | `permissionDecision` | effect |
|---|---|---|
| `observe` | *(none — return before printing)* | feed line only, no injected text |
| `warn` | `allow` | edit proceeds, reason surfaces as a visible warning |
| `ask` | `ask` | user is prompted |
| `deny` | `deny` | write is refused, reason points at the existing `file:line` |

A mistyped mode falls through the same `match` to no output ([guard.rs:233](../../../cli/src/guard.rs#L233)) — it can never enforce — while the degraded string still rides the observe feed's `mode` field ([probe.rs:245](../../../cli/src/guard/probe.rs#L245), [probe.rs:236-264](../../../cli/src/guard/probe.rs#L236)) and the health line.

Tier resolution is per rule class, not global: an explicit `[guard] mode` overrides the two classes `[guard]` owns (the T1/T2 duplicate write and the hard budget); otherwise the §4.2 route default for that class applies ([tier.rs:42-48](../../../cli/src/config/tier.rs#L42)). Tombstone and flow decide at `[tombstone] tier` / `[flow] tier`, which `[guard] mode` does not reach, and the armed zone at its mapped tier. The route default for the two promoted `PreToolUse` classes is a single constant read by both `guard.rs` and `health.rs`, so the enforced tier and the reported tier cannot drift:

```
PROMOTED_DEFAULT = "deny"     // tier.rs:36
```

([tier.rs:36](../../../cli/src/config/tier.rs#L36); consumed at [guard.rs:84](../../../cli/src/guard.rs#L84) and [health.rs:59](../../../cli/src/health.rs#L59)). Other classes remain unpromoted under the class-specific admission rule below ([DEVELOPMENT_PLAN.md:101-103](../../DEVELOPMENT_PLAN.md#L101)); the zone and changeset ledgers now provide measurements, with neither licensing a default change in this batch.

When several rules fire on one write, the decision line is emitted at the **strongest** tier among them, ranked by index in `TIERS` (unknown values rank 0 = `observe`): class rules carry the class mode, the zone rule carries its own mapped tier, so a zone warn never rides a deny-class escalator ([guard.rs:173-211](../../../cli/src/guard.rs#L173)). A broken `ce.toml` overrides the computed tier down to a visible `warn` that names the parse error ([guard.rs:205-209](../../../cli/src/guard.rs#L205)).

### The FPR gate that promotes a class

The ladder is a **route**, written into the plan so the default can neither stay at `warn` forever nor start at `deny` ([DEVELOPMENT_PLAN.md:96-103](../../DEVELOPMENT_PLAN.md#L96)):

1. 0.x (M3–M4): default `warn`; `deny` exists as an opt-in capability.
2. After the M4 FPR gate passes: **T1/T2 exact duplicate write** and **hard-budget breach (file > 750 lines)** promote to `ask`.
3. 1.0 (M7): those two classes promote to `deny`; every other rule stays `observe` for want of its own FPR record. Each default change records its FPR evidence in the CHANGELOG.

The gate itself is quantitative and appears in two places with two shapes. The M3 acceptance criterion is **≤ 1 mis-block in 500 real normal edits**, with `N=1` demonstrations explicitly disallowed ([DEVELOPMENT_PLAN.md:284](../../DEVELOPMENT_PLAN.md#L284)); the M4 main gate is **FPR ≤ 1% over 500 real normal edits**, on a pre-registered evaluation set frozen before implementation, ≥ 200 edit samples, ≥ 50% from real agent transcripts ([DEVELOPMENT_PLAN.md:285](../../DEVELOPMENT_PLAN.md#L285)). Risk register R4 states the admission rule flatly: **deny admission = the M4 FPR gate (≤ 1%)** ([DEVELOPMENT_PLAN.md:320](../../DEVELOPMENT_PLAN.md#L320)).

Sample purity is part of the gate, not an afterthought: only observe-mode sessions and pre-M3 no-guard sessions may be sampled, edits the guard already intervened in are excluded and the exclusion ratio reported — otherwise FPR is biased downward by the guard's own shaping and the deny admission becomes self-certifying ([DEVELOPMENT_PLAN.md:285](../../DEVELOPMENT_PLAN.md#L285)). This is why every probed event is appended to `<root>/.ce/observe.ndjson` in **all** modes ([guard.rs:7-8](../../../cli/src/guard.rs#L7)) and why the feed carries `session_id`: the evaluation set is partitioned by session, and neither the dogfood-session count nor the purity rule is answerable without it ([envelope.rs:22](../../../cli/src/guard/envelope.rs#L22), [hookio.rs:134-136](../../../cli/src/hookio.rs#L134)).

#### The recorded replay

The M3 replay treats git linear history as a real edit stream: each changed code file in each commit is one "write the child version's content into the parent state" event, materialized incrementally in a shadow directory, **probe first, then apply**; guard ran at default knobs `t = 50 / min_distinct = 7` ([FPR-REPLAY.md:10-15](../../FPR-REPLAY.md#L10)). Those two knobs are the shipped defaults: `t = window + kgram - 1 = 26 + 25 - 1 = 50` tokens, aligned to the jscpd `min-tokens` default ([mod.rs:274-300](../../../cli/src/dedup/mod.rs#L274)), and the diversity floor `7`, calibrated because arbitrated data-row false positives measured `distinct <= 6` while arbitrated true clones measured `>= 7`. Since proto 2.19.0 (batch-7 slice 1) the floor's AUTHORITY is the core's ([CE/Dedup/Cost.hs](../../../core/app/CE/Dedup/Cost.hs)): `ce dedup --check` ships the pre-filter distinct counts, the core re-derives the admitted count and judges the budget from its own number, and since plan v2.33 W3 Rust keeps no copy: the measuring side reads `minDistinct` off the core's package ([pairs.rs:80-87](../../../cli/src/dedup/pairs.rs#L80)), and two legs still hold the judging core to it — the knob-face pin in core_wire and the per-run `dedupBlocks` ensure in budget.rs. On the `--check` road an override may only tighten those two knobs (`--min-tokens` > 50, `--min-distinct` > 7 or `0` are refused by name — [budget.rs:33](../../../cli/src/dedup/budget.rs#L33)), so the operating point the replay measured is the one the gate judges at.

### The hard-budget rule

Scope is decided **before** any disk read — language arm, then exclude walk — so the hook never pays an unbounded read for a file it is about to declare out of scope ([budget.rs:53-62](../../../cli/src/guard/budget.rs#L53)). The rule then fires iff the write grows the file past its line:

```
cap    = lines_for(file).file_lines_fail     // the file's class table; 750 for class 0
breach ⇔ cap != 0 ∧ after > cap ∧ after > before
```

([zone.rs:109-126](../../../cli/src/guard/zone.rs#L109); default `file_lines_fail = 750`, [ce-toml.md:18](../ce-toml.md#L18)). `before` is the file's size before the write — 0 for a file that does not exist yet — counted from the bytes with a streaming reader (newlines, plus one when the file is non-empty and does not end in one: the value `str::lines` gives on the same bytes), with no size cap and no UTF-8 requirement, so only a real I/O failure leaves it unread ([size.rs:21](../../../cli/src/scan/metrics/size.rs#L21)); an Edit takes it from the one read that applied the edit ([applied.rs:121](../../../cli/src/guard/applied.rs#L121)). Until v2.35 the rule was `after > cap` alone, and a file already past its line refused every write — the one that shrank it included — so the reason's own advice, split the file, could not be followed one step at a time. A breach now has three kinds, each named on its feed line and in its sentence: a **crossing** (the file was at or under the line, or did not exist), a **growth** (it was already past the line and grows), and an **unread** prior (refused as the rule stood, the line stamped degraded). A write past the line that does not grow the file is **carried**: its `budget` line says `carried: true` and no reason is spoken ([budget.rs:134-147](../../../cli/src/guard/budget.rs#L134)). A growth speaks at the class tier, like a crossing; no second tier exists, and a ledger reading past the bar would mean the growth refusal needs a tier of its own before the rule may ship. The predicate is the measuring side's, unlike the class's sentences: the budget class is the hook's daemon-free class by design — it holds when no daemon can start — and splitting one two-clause comparison across the two languages would make the hook's hardest refusal depend on a warm core. Since the rulepack's hook slice (plan v2.13 ① P4) the line is the **file's own**: `lines_for` compiles the declared `[[rules.class]]` set once per hook run and takes the class's effective table, the global one for class 0 — the same reading the scan gate and the score take, so the hook denies at exactly the line the CI wall would fail at ([budget.rs:17-29](../../../cli/src/guard/budget.rs#L17), [zone.rs:203-216](../../../cli/src/guard/zone.rs#L203)); the graded zone reads its H and its warn fallback from the same table. The `cap == 0` guard is load-bearing: it encodes "no hard line exists" per the P3 grade-table contract, where a naive comparison read `0` as "every write breaches" ([budget.rs:134](../../../cli/src/guard/budget.rs#L134)). Since 6.4.0 the table the hook reads is the FENCED one: with a committed baseline whose digest differs from the declared config's — or one that cannot be read — `thresholds`, `exclude` and the classes are taken at their shipped values and the deny reason names the fence, because a drifted config is an unverified document and a hook that kept any part of it would let the edit that produced the drift choose its own budget; `[guard]` mode stays as declared, a mode being a visible act rather than a budget ([zone.rs:174-180](../../../cli/src/guard/zone.rs#L174)). Every write past the line gets its own `budget` feed line in **every** tier, refused or carried, with `before_lines` beside `resulting_lines`, because the step-3 decision at 1.0 needs per-rule records ([budget.rs:157-182](../../../cli/src/guard/budget.rs#L157)) — the feed's `budget` event was added in schema `0.4.0` for exactly that reason ([hookio.rs:132](../../../cli/src/hookio.rs#L132)).

The hard-budget class now has its own ledger (v2.35). `cli/tests/it/fpr_budget_replay.rs` walks the same first-parent histories as the zone ledger, through the same walk (`common::policy`: the hook's `sized_path` population, the parent commit's fenced config and scope), and records every write past the line with its kind; `contracts/eval/fpr-budget-v1.json` freezes the eight corpora and `fpr_budget_gate.rs` re-derives every number and pins the page's wording. It carries two readings: every refusal counted, and — a definition, not a measurement error — a refusal counted false when the wall's verdict on that file did not change, which is a growth of a file the parent already failed on. Measured, the old rule against the new over the same events: self 0.0515 % → 0.0515 % (five crossings, nothing carried); requests 42.4107 % → 28.1250 % (190 old refusals: 3 crossings, 123 growths, 64 carried). The full table is [FPR-REPLAY.md](../../FPR-REPLAY.md).

### `zone_tiers`: the opt-in position-to-tier map

Below the hard line, a write landing in the graded zone `(S, H]` is scored by position. Position is integer per-mille:

```
S = committed baseline softLine, else the file's file_lines_warn    // its class's, else the global 300
H = the file's file_lines_fail                                      // its class's, else the global 750
permille = (lines - S) * 1000 / (H - S)
```

([zone.rs:68-72](../../../cli/src/guard/zone.rs#L68); `S` is read off the committed `ce-baseline.json` through `zone::envelope`, [zone.rs:131-143](../../../cli/src/guard/zone.rs#L131); `file_lines_warn = 300`, [ce-toml.md:17](../ce-toml.md#L17)). A degenerate zone — `H == 0` (no hard line), `H <= S`, or `lines <= S` — logs nothing rather than fabricating a position ([zone.rs:68-70](../../../cli/src/guard/zone.rs#L68)).

The map is a three-way partition on that per-mille ([zone.rs:71-79](../../../cli/src/guard/zone.rs#L71)):

```
0   ..= 249  →  observe
250 ..= 750  →  warn
751 ..       →  ask
```

At the default `S = 300`, `H = 750` (so `H - S = 450`), integer division puts the boundaries at `lines >= 413` for `warn` and `lines >= 638` for `ask` — derived from the constants above, not stated in the source.

The switch is **off by default** and changes one repo only: `[guard] zone_tiers`, default `false` ([tier.rs:24-28](../../../cli/src/config/tier.rs#L24), [ce-toml.md:32](../ce-toml.md#L32)). Disarmed, the zone is feed-only — a `zone` line is written in every tier and `zone_assess` returns `None`, injecting nothing ([budget.rs:235-245](../../../cli/src/guard/budget.rs#L235)). Armed, the resolved tier is additionally stamped as `zone_tier` on the feed line, so the record says what the rule *did*, not only where the write landed ([budget.rs:232-234](../../../cli/src/guard/budget.rs#L232), [hookio.rs:122-125](../../../cli/src/hookio.rs#L122)). Since v2.35 a tier fires only on a write that grows the file: a write that keeps or shrinks it logs `carried: true` and `zone_tier: observe`, the hard budget's own reading below its line ([budget.rs:212-214](../../../cli/src/guard/budget.rs#L212)).

The declaration ties any default flip to the zone's own FPR record ([tier.rs:24-28](../../../cli/src/config/tier.rs#L24)); the `zone` event supplies that record ([hookio.rs:127-130](../../../cli/src/hookio.rs#L127)). First measurement: self 28/5196 = 0.5388 % (Clopper–Pearson 95 % upper bound 0.7778 %), requests 11/448 = 2.4553 % (upper bound 4.3507 %); the latter is over 1 %, so variant B applies — `zone_tiers` stays `false` by default, no default tier change. The v2.35 re-freeze moved both the population and the rule (growth only): self 184/9707 = 1.8955 % (upper bound 2.1868 %) at ce00d731, requests 5/448 = 1.1160 % (upper bound 2.5852 %); both are over 1 %, so the default stands.

That ledger now exists (plan v2.29 step 10). `cli/tests/it/fpr_zone_replay.rs` replays a first-parent history the way the two older instruments do — every changed in-scope file of every commit is one Write event, judged against the two lines the hook would have read AT THAT COMMIT (S from the parent's committed baseline, H from the file's own class table) through `zone::landing`, the very function `zone_assess` calls, so the instrument cannot drift from the rule it measures. Scope is reproduced rather than approximated: a scratch root carries the parent commit's `ce.toml`, `ce-baseline.json`, `.gitmodules` and ignore files, and `Config::load`, `walk::Scope` and `Classes` are pointed at it. An ask that ALSO crosses H is not the zone's: `budget::size_classes` reaches `zone_assess` only in the `else` arm of the hard-budget rule, so those are counted apart as shadowed and subtracted from the false count, never from the denominator ([budget.rs:134-154](../../../cli/src/guard/budget.rs#L134)). Since v2.35 the walk is the one the hard-budget ledger shares (`common::policy`): its population is the hook's own (`Lang::sized_path`, which includes the scan-only arm), and each event carries the file's size before the write, so a carried write is counted at observe as the hook counts it. The measured rows, every intercept among them, are frozen in `contracts/eval/fpr-zone-v1.json` and read back by `cli/tests/it/fpr_zone_gate.rs`, which holds the SHIPPED default equal to what that arithmetic licenses — armed only if every corpus measured at or under the §4.2 line. The ledger itself, with the definitions and the decision rule written down before the numbers, is [FPR-REPLAY.md](../../FPR-REPLAY.md).

### Injection budget: warns are rate-limited, enforcement is not

An anti-bloat tool must not itself become a context entropy source (§4.4 B4). Two mechanisms:

- **Per-(rule, file, session) suppression.** A warn fires once per session per file per rule; the observe feed *is* the accumulator, consulted **before** the current event lands in it so a warn cannot read its own fresh line as "already warned" ([guard.rs:95-102](../../../cli/src/guard.rs#L95), [budget.rs:216-218](../../../cli/src/guard/budget.rs#L216), [feed.rs:56-74](../../../cli/src/hookio/feed.rs#L56)). Suppression is skipped entirely when `mode ∈ {deny, ask}` — enforcement is not context bloat and repeats every time it holds ([guard.rs:97-99](../../../cli/src/guard.rs#L97)); an armed zone `ask` likewise repeats, only `warn` is budgeted ([budget.rs:218](../../../cli/src/guard/budget.rs#L218)). Counting is conservative in the reporting direction: a clean probe line (`matches` no more than `relocated`), a carried budget line and an unarmed zone line (`zone_tier` absent or `observe`) never count as "already warned", and any read or parse failure returns "not warned" — fail open toward *reporting*, the opposite bias from enforcement's fail-open ([feed.rs:43-54](../../../cli/src/hookio/feed.rs#L43)).
- **Token clip at the single emission throat.** `WARN_BUDGET_TOKENS = 200`, `STOP_BUDGET_TOKENS = 400`, converted to chars by one declared measurement constant `CHARS_PER_TOKEN = 4` ([hookio.rs:259-261](../../../cli/src/hookio.rs#L259)); the clip is char-boundary safe and appends `… (clipped; full report in .ce/observe.ndjson)`, pointing at the full on-disk record ([hookio.rs:275-287](../../../cli/src/hookio.rs#L275), applied at [guard.rs:214-218](../../../cli/src/guard.rs#L214)).

The feed schema is a versioned contract pinned by a golden fixture — <!--ce:report:observe#schemaver-->`ce.observe/0.14.0`<!--/ce--> today ([hookio.rs:137](../../../cli/src/hookio.rs#L137)) — bumped on any shape change and on the one recorded SEMANTIC break: `0.7.0` re-defines `matches` on probe events as the NOVEL count (the subtraction above), because pre/post counts are not comparable as FPR raw material; `0.8.0` adds the additive `tombstone` event and key (plan v2.26, feed-only); `0.9.0` moves the tombstone counts under the core's `judged` (a named break of a shape no release carried); `0.10.0` adds the additive `similar` object on `stop_audit` lines (plan v2.29, the same-role advisor's ledger line); `0.11.0` adds `tool_use_id` on every line the PreToolUse hook writes, `decision` on `probe` lines and the `settled` event the PostToolUse leg writes when the tool ran after an `ask` (plan v2.30 step 5b: the person's decision, which no PreToolUse line could record); `0.12.0` adds the `flow` event and the optional `flow` object on audit lines (plan v2.31 step 5); `0.13.0` adds the one line a hook left inert by an unreadable definition package writes, `degraded` with its `reason` (plan v2.32 step 2 follow-up); `0.14.0` adds `before_lines` and `kind` or `carried` on `budget` lines, `before_lines` and `carried` on `zone` lines, `unapplied` and `relocated` on `probe` lines, and `reindex` on `settled` lines (v2.35); the `zone_tier` key arrived at `0.6.0`, the `zone` event at `0.5.0`, the `budget` event at `0.4.0`, and `session_id` at `0.2.0` ([hookio.rs:23-106](../../../cli/src/hookio.rs#L23)). That versioning is what makes the FPR ledger replayable across releases rather than a claim about a build nobody can reconstruct.
