# Scoring and the ADR-006 ratchet

[index](../methodology.md) · [← 04 Structure judgment — tree-scale entropy, eight axes](04-structure-judgment-tree-scale-entropy-seven.md) · [→ 06 Graph liveness and dead-code verdicts](06-graph-liveness-and-dead-code-verdicts.md)

Everything in this section is computed in `ce-core` (Haskell), from the fact tables that arrive over the `verdict.request` wire. It is pure integer/`Rational` arithmetic — no floating point, no logarithms — so the same request always yields the same verdict.

### The aggregate score

Since proto 10.0.0 (plan v2.35) the score is the **extent law**: the share of the repository's lines that a finding names, read once over the whole tree ([ExtentFacts.hs:50-57](../../../core/app/CE/Verdict/ExtentFacts.hs#L50), [Extent.hs:154-158](../../../core/app/CE/Verdict/Extent.hs#L154)):

```
score = max 0 (floor (scale · (1 − k · E / L)))     -- L = 0 reads the scale
k     = violCost / violCostNeutral                    -- 10 / 10 at the neutral dial
L     = the sum of every universe file's line count
E     = the sum over files of E_f, weighted by layers (below)
```

`scale = scoreScale = 1000` ([Cost.hs:254-255](../../../core/app/CE/Verdict/Cost.hs#L254)), `violCost = 10` ([Cost.hs:207-208](../../../core/app/CE/Verdict/Cost.hs#L207)) and `violCostNeutral = 10` ([Cost.hs:230-231](../../../core/app/CE/Verdict/Cost.hs#L230)): the score is an integer per-mille value opening at 1000, polarity higher-is-better ([DEVELOPMENT_PLAN.md:71](../../DEVELOPMENT_PLAN.md#L71)). Every quantity is exact `Rational` and the score floors once. At the neutral dial a tree whose every line is named scores 0, and a line named by two findings counts once: E is a count of lines, never of findings.

**One file's extent.** For a file of `n` lines ([Extent.hs:74-83](../../../core/app/CE/Verdict/Extent.hs#L74)):

```
E_f = min(n, max(T, n − S, churn))
```

- `T`, the **named lines**: the union of the lines the families locate in the file — a duplicate member's span (clone axis for kinds 0 / 1, docdup axis for kind 2), every line of an unreferenced file (axis 4, off unless named; below), a reference line inside its source's cycle (axis 6; a self reference counts only at a cycle floor of 1) ([ExtentFacts.hs:84-99](../../../core/app/CE/Verdict/ExtentFacts.hs#L84)) — read over the forest of all the file's functions by span containment, where a function over its cognitive ceiling `C` with complexity `c` names `m · (1 − C/c)` of its `m` lines, or the named lines inside it if those are more ([Extent.hs:100-113](../../../core/app/CE/Verdict/Extent.hs#L100)).
- `n − S`, the **size term**: the lines past the file's soft line, `0` at or under it. A prose-only file (in the `proseLines` table) has no size term ([ExtentFacts.hs:61-82](../../../core/app/CE/Verdict/ExtentFacts.hs#L61)).
- `churn`, the **churn excess** of a rewrite-heavy file: `n · (1 − t · (rw + ap) / rw)` at rewrite ratio `t = rewriteNum / rewriteDen = 50/100` ([ExtentFacts.hs:101-110](../../../core/app/CE/Verdict/ExtentFacts.hs#L101), [Cost.hs:109-113](../../../core/app/CE/Verdict/Cost.hs#L109)).

The maximum, not a sum: the size term and the named lines are two readings of the same file's lines, so a long file whose clone is inside its overhang is not counted twice. A size row outside the verdict universe (a scan-only file) contributes its size term alone.

| code | axis | lines it names | knob(s) and value |
|---|---|---|---|
| 0 | size | the file's lines past its soft line `S` | `S` from the baseline (below); `sizeCeil = 300` without one ([Cost.hs:164-165](../../../core/app/CE/Verdict/Cost.hs#L164)) |
| 1 | complexity | `m · (1 − C/c)` per function over the ceiling | `cocCeil = 15` ([Cost.hs:199-200](../../../core/app/CE/Verdict/Cost.hs#L199)) |
| 2 | clone | the member spans of verified pairs, kinds 0 (T1/T2) and 1 (T3) | the clone family's own bars |
| 3 | docdup | the member spans of verified docdup pairs (kind 2) | the docdup family's own bars |
| 4 | deadcode | every line of an unreferenced file — one the graph cannot reach (booklet 06 §10) | the graph's reachability; default weight `0` — on only when `[score.weights] deadcode` names it (`optInAxes = [4]`, [Cost.hs:246-247](../../../core/app/CE/Verdict/Cost.hs#L246)) |
| 5 | churn | the churn excess of a rewrite-heavy file | `rewriteNum/rewriteDen = 50/100` |
| 6 | graph_cycle | the reference lines inside the source's cycle | `cycleFloor` = `[graph] scc_floor`, `2` shipped ([Score.hs:66-75](../../../core/app/CE/Verdict/Score.hs#L66)) |

The four tables the law reads ride on every request — `contSpans` (each continuous row's file and span), `dupSpans` (every verified pair's two member spans), `refLines` (every judged arc's source line), `proseLines` (the line count of each prose-only file) — and their contract is the boundary's ([ExtentRows.hs:28-31](../../../core/app/CE/Verdict/ExtentRows.hs#L28)). The reply carries `extent` = `{tenths, lines}`: E times ten, rounded half up (an integer, at most ten times `lines`), and L. The exact E never leaves the fold, where the score is floored on it: its reduced denominator is the least common multiple of data-dependent denominators (a function's c, a file's rewritten lines) and has no bound in 64 bits. Each axis row is that axis's **own** share, `floor(scale · E(axis alone) / L)`, unweighted and without `k` ([Extent.hs:169-177](../../../core/app/CE/Verdict/Extent.hs#L169)); the `ce.check-report` document carries the same `{tenths, lines}`, so that every face prints the core's one rounding ([Extent.hs:166-167](../../../core/app/CE/Verdict/Extent.hs#L166)).

**Where the complexity values come from.** A `metricCode = 1` value is the function's cognitive complexity as `scan/1` derived it in the core from the measuring side's structural events — the SonarSource whitepaper v1.7 rules ([Complexity.hs:1-24](../../../core/app/CE/Scan/Complexity.hs#L1)) plus the recursion increment ([Cycles.hs:1-20](../../../core/app/CE/Scan/Cycles.hs#L1)). The derivation is held to a second spelling that reads structure trees instead of events — a fold with the nesting level as an explicit argument, and the cycle set from a closure of the call relation — and the core must echo its numbers on 1,200 seeded programs in three table families, the whitepaper register's 38 lines and 300 call graphs ([ReferenceScan.hs:1-27](../../../core/test/ReferenceScan.hs#L1), [ScanReferenceProps.hs:1-11](../../../core/test/ScanReferenceProps.hs#L1)). A boolean chain's operators arrive as class ids, one per entry of the language's `coc_operators` table, and an entry may list several spellings of one operator: the C family's `&& and` and `|| or` make C++'s alternative tokens the operator they spell, so `a && b and c` is one run of like operators ([C.hs:120](../../../core/app/CE/Lang/C.hs#L120)).

**Weights, by layers.** Each axis carries an effective weight: the wire's `weights` table supplies `[axisCode, w]` rows, the first matching row wins, and an unlisted axis takes `defaultWeight = 1` — except an opt-in axis, which weighs `0` unless a row names it ([Score.hs:83-88](../../../core/app/CE/Verdict/Score.hs#L83), [Cost.hs:236-237](../../../core/app/CE/Verdict/Cost.hs#L236)). Since plan v2.35 the opt-in axes are `optInAxes = [4]`, the dead axis alone: a class that may not block by default may not pull the score under a floor by default either, so seven axes exist and <!--ce:count:default_axes#word-->six<!--/ce--> count unless a project names the seventh ([Cost.hs:238-247](../../../core/app/CE/Verdict/Cost.hs#L238); the definition package publishes the list as `limits.score_opt_in` for the knob digest's shipped table). With `r_i = w_i / max w` and the distinct positive ratios in falling order `r_1 > r_2 > …` (`0` after the last), `E = Σ_j (r_j − r_{j+1}) · E(the axes with r_i ≥ r_j)` ([Extent.hs:147-152](../../../core/app/CE/Verdict/Extent.hs#L147)): equal weights read E over every axis at once, a weight `0` removes its axis, and a heavier axis's lines count fully before the lighter axes' lines join them — so a line two axes name is still counted once in every layer. The same lookup builds the echoed table `0..6` in the reply. The boundary holds the table's shape ([Table.hs:80-90](../../../core/app/CE/Verdict/Table.hs#L80)) and refuses one that leaves every EFFECTIVE weight at `0` ([Wire.hs:191-194](../../../core/app/CE/Verdict/Wire.hs#L191)) — so zeroing the other six axes without naming `deadcode` is refused, as zeroing all seven is.

**With the dead axis off**, an unreferenced file is an ordinary file to the score: its lines are in `L` and none of them is charged, so adding one raises the share of clean lines and deleting one lowers it, as for any clean file. "Deleting an unreferenced root never lowers the score" holds only with the axis on. The battery pins both: with row 4 named `1`, deleting a dead root never lowers the score; with it off, a 10-line file a duplicate span names beside an unreferenced root of 3 lines over a dependent of 5 scores 444, and 333 once the root is deleted ([VerdictExtentProps.hs:34-35](../../../core/test/VerdictExtentProps.hs#L34)).

An over-cap request never gets a partial judgment: it returns a fully-shaped degraded reply with `score = 0`, empty axes, and `fail = true` with reason `verdict_too_large` ([Verdict.hs:204-218](../../../core/app/CE/Verdict.hs#L204), [Verdict.hs:219-254](../../../core/app/CE/Verdict.hs#L219)). Caps are `verdictNodeCap = 131072` nodes and `verdictRowCap = 524288` rows ([Cost.hs:263-267](../../../core/app/CE/Verdict/Cost.hs#L263)), the row count summing every fact, extent and knob table plus the baseline's rows ([Verdict.hs:58-86](../../../core/app/CE/Verdict.hs#L58)).

The density law this replaced (proto 2.17.0 to 9.x: a per-axis charge `floor(scale · v/(v+n))` over each axis's opportunity, folded by weight) is recorded in the wire ledger ([VERSIONING.md](../../../contracts/VERSIONING.md), the 10.0.0 entry); scores are not comparable across the change.

### The soft line (axis 0)

The size term reads one line per file, `S`. `S` is relative to the repository, not a constant. Over the multiset of judged-language LOC values (positives only), with `m` the log-space median and `r` the multiplicative MAD ([Soft.hs:69-80](../../../core/app/CE/Verdict/Soft.hs#L69)):

```
m² = x_lo · x_hi                       -- the two middle LOC values (an odd count: its one middle, twice)
r⁴ = ρ²_lo · ρ²_hi,  ρ² = max(x²/m², m²/x²)   -- the two middles of ρ²; >= 1 by construction
S  = clamp(⌊(m²·m²·(r⁴)^k)^(1/4)⌋, [softMin, min softMax H])
```

This is `S = clamp(median + k·MAD, ...)` in log-LOC space, exponentiated, read in fourth powers so no logarithm and no root of a rational is ever taken: the median of an even log sample is the mean of its two middle logs — the log of the GEOMETRIC middle `√(x_lo·x_hi)` — so `m²` and `r⁴` are plain products, `S = ⌊m·r^k⌋` is an exact integer fourth root, and the identity holds for every count. Before proto 9.0.0 an even count took the arithmetic mean of the two middles — for `m`, and again for `r` around that `m` — and missed the definition in either direction: at `k = 2`, `{150, 200, 250, 300}` derived 339 where the definition gives 335 (lenient), `{34, 57, 78, 183, 222, 224}` derived 381 where it gives 416 (strict). An odd count derives exactly what it did. All order statistics are over `Rational` ([Soft.hs:1-17](../../../core/app/CE/Verdict/Soft.hs#L1), [Soft.hs:44-52](../../../core/app/CE/Verdict/Soft.hs#L44)). `k = softLineK = 2`, calibrated over self + requests + ripgrep, where it put `S` near the historical 300 on each — an observation on three trees, never an invariant. `S` travels with the distribution it is derived from, and this repository's own has since left that neighbourhood; what bounds it is the clamp, and where the live value lives is the committed baseline ([Cost.hs:174-186](../../../core/app/CE/Verdict/Cost.hs#L174)). The clamp fence is `[softMin, softMax] = [200, 500]`, declared structural rather than a knob — and since 9.0.0 the establish caps it at the effective hard line, `min softMax H`, so a committed `S` never sits above `H` ([Verdict.hs:147-148](../../../core/app/CE/Verdict.hs#L147), [Cost.hs:188-195](../../../core/app/CE/Verdict/Cost.hs#L188)). `floor` is the conservative direction: a lower `S` names more lines ([Soft.hs:54-60](../../../core/app/CE/Verdict/Soft.hs#L54)). An empty or all-empty LOC set yields `Nothing` — absence, never a fabricated line ([Soft.hs:70-80](../../../core/app/CE/Verdict/Soft.hs#L70)).

`S` is derived **only at establish** (no baseline present) and then frozen into the new baseline; every later run judges with the committed `S`, and a pre-v0.6 baseline carrying no `softLine` falls back to the `sizeCeil` knob `300` ([Verdict.hs:140-149](../../../core/app/CE/Verdict.hs#L140), [ExtentFacts.hs:64](../../../core/app/CE/Verdict/ExtentFacts.hs#L64), [Cost.hs:160-165](../../../core/app/CE/Verdict/Cost.hs#L160)). Because only the establish path reaches the derivation, re-anchoring the soft line requires `CE_ACCEPT_BASELINE` by construction ([Faces.hs:59-62](../../../core/app/CE/Verdict/Faces.hs#L59)). Since plan v2.18 step #14 the CLI reaches that path only under the act: a missing `ce-baseline.json` refuses by name instead of establishing, a present file that is not a baseline document is an error before any measurement, and `ce baseline` persists at the project root alone — a scope below it refuses before the core is spawned ([main_score.rs:108-137](../../../cli/src/main_score.rs#L108), [main_score.rs:169-187](../../../cli/src/main_score.rs#L169), [baseline.rs:121-133](../../../cli/src/score/baseline.rs#L121), [baseline.rs:205-217](../../../cli/src/score/baseline.rs#L205)).

**Per-class lines (proto 3.1.0, plan v2.13 ①).** A continuous row may carry a fourth column, the file's *path class* — the 1-based index of the first `[[rules.class]]` whose globs match it, `0` for none — and the request may carry a `classKnobs` table `[classId, code, value]` whose first three codes are the ceilings' own `0 / 1 / 2` (`sizeCeil` / `cocCeil` / `sizeHard`) under a class, joined at 5.1.0 by `classTolCode = 3` — the class's own ADR-006 ratchet allowance — and at 6.4.0 by `classCocTolCode = 4`, its cognitive-complexity sibling, which where declared replaces code `3` for metric `1` alone; those two are the class knobs whose value `0` is meaningful ([Cost.hs:137-144](../../../core/app/CE/Verdict/Cost.hs#L137), [Cost.hs:146-158](../../../core/app/CE/Verdict/Cost.hs#L146)). The rows fold into one `Map` per judgment ([Facts.hs:36-39](../../../core/app/CE/Verdict/Facts.hs#L36), built once in [Verdict.hs:136-137](../../../core/app/CE/Verdict.hs#L136)) and a row's class is its fourth column or `0` ([Facts.hs:43-46](../../../core/app/CE/Verdict/Facts.hs#L43)); the size term reads a classed row against its class's own soft line (code `0`) where declared, falling back to the tree's `S`, and the complexity term against its class's ceiling (code `1`) ([ExtentFacts.hs:61-82](../../../core/app/CE/Verdict/ExtentFacts.hs#L61)). Code `2`, the class's hard line, no longer reaches the score since 10.0.0 (the law has no curve); the split advisory still prices a classed file's seams against it (booklet 08). The law is untouched — only the lines a row is measured against move — so an unclassed repository judges byte-for-byte as before. The ratchet reads the class off the current row and spends it on the *allowance* alone — a declared `classTol` replaces both global legs ([Ratchet.hs:135-143](../../../core/app/CE/Verdict/Ratchet.hs#L135), bound at [Verdict.hs:155-161](../../../core/app/CE/Verdict.hs#L155)) — while what it writes back is still the three-column prefix ([Ratchet.hs:151](../../../core/app/CE/Verdict/Ratchet.hs#L151)): a class is a charging parameter, never a baseline fact, and the baseline stays three columns. At the boundary a table mixing three- and four-column rows refuses ([Table.hs:38-41](../../../core/app/CE/Verdict/Table.hs#L38)), a class past `classCap = 64` refuses (64 itself is admitted) ([Cost.hs:84-85](../../../core/app/CE/Verdict/Cost.hs#L84), [Rows.hs:89-98](../../../core/app/CE/Verdict/Rows.hs#L89)), and the knob rows obey the ceilings grammar one class dimension wider — class `0` has no override channel, `(classId, code)` strictly ascending, the code bounded at `classKnobMaxCode = 4` and the value floor judged per code, `0` for the two allowances and `1` for the ceilings ([Table.hs:51-69](../../../core/app/CE/Verdict/Table.hs#L51)); that ordering is a validation fact, never a judgment fact (`ClassProps` pins the permutation). Names and globs never cross the wire; the index does.

### The continuous ratchet

ADR-006 defines per-file/per-function ceilings on continuous metrics (file LOC, function CoC): the ceiling is the baseline value; exceeding it fails, and coming in under it tightens the ceiling automatically. A single edit is allowed `+2%` or `+10` lines, whichever is larger — on a function's complexity row `+2%` or `+1` point (proto 9.0.0) — and consumed tolerance is reported in the `ce check` ratchet line ([DEVELOPMENT_PLAN.md:204-211](../../DEVELOPMENT_PLAN.md#L204)).

As built ([Ratchet.hs:78-82](../../../core/app/CE/Verdict/Ratchet.hs#L78), [Ratchet.hs:138-141](../../../core/app/CE/Verdict/Ratchet.hs#L138)) the law has two arms — the row's class allowance first, the global legs only when the class declares none:

```
tolerated(m, Just t, c)  = c + t                                         -- the class's own allowance (5.1.0)
tolerated(m, Nothing, c) = max (c * tolNum `div` tolDen) (c + abs m)    -- the global legs
abs 0 = tolAbs        -- a file-lines row: lines
abs 1 = tolAbsCoc     -- a function's cognitive-complexity row: points (9.0.0)
```

with `tolNum/tolDen = 102/100` and `tolAbs = 10` ([Cost.hs:120-127](../../../core/app/CE/Verdict/Cost.hs#L120)), and `tolAbsCoc = 1` ([Cost.hs:134-135](../../../core/app/CE/Verdict/Cost.hs#L134)). Until 9.0.0 the `+10` lines leg applied to the complexity rows as well, so a function at ceiling `15` could reach `25` in one edit — a `+67%` allowance nobody wrote down. On the global arm, integer `div` truncates down — the conservative side, the "ties don't open" stance — and the two legs cross at ceiling `500` on a lines row and at `50` on a complexity row, with one property assertion pinned on each side ([Ratchet.hs:63-69](../../../core/app/CE/Verdict/Ratchet.hs#L63), [Cost.hs:115-118](../../../core/app/CE/Verdict/Cost.hs#L115)). A class that declares `ratchet_tolerance` (classKnobs code `3`, or `cognitive_ratchet_tolerance` — code `4`, 6.4.0 — which answers the fn-CoC rows alone where declared) **replaces both legs** with that absolute allowance — absolute rather than proportional because the classes wanting the knob are vendored trees and frozen fixtures, and a percentage of a large file is exactly the unearned growth the plan objected to; `t = 0` therefore means any growth at all is over, and the global `max(+2%, +10)` is never consulted ([Ratchet.hs:71-82](../../../core/app/CE/Verdict/Ratchet.hs#L71), K14 at [ClassProps.hs:221-227](../../../core/test/ClassProps.hs#L221)).

The metric code is `0` (file lines) or `1` (function cognitive complexity) and nothing else: the live rows and the baseline both refuse any other code by name against `metricTop = 1` ([Cost.hs:95-96](../../../core/app/CE/Verdict/Cost.hs#L95)) — until 9.0.0 they borrowed `scan/1`'s grade-table top, `6`, and codes `2..6` were ratcheted but never charged. For each current row `[u, metricCode, v]` matched against the baseline ceiling `bv` for the same `(entity, metric)` key ([Ratchet.hs:84-88](../../../core/app/CE/Verdict/Ratchet.hs#L84)):

- `v > tolerated(bv)` → **over**, emitted as `[u, c, v, allowed]` ([Ratchet.hs:110-115](../../../core/app/CE/Verdict/Ratchet.hs#L110)). Note the comparison is strict, so `v == tolerated(bv)` is tolerated, not over.
- `bv < v <= tolerated(bv)` → **tolerance drawn**, emitted as `[u, c, v - bv]` for the Stop summary ([Ratchet.hs:115-120](../../../core/app/CE/Verdict/Ratchet.hs#L115), [Ratchet.hs:51-53](../../../core/app/CE/Verdict/Ratchet.hs#L51)).
- new ceiling = `min(v, bv)` — auto-tighten; an entity the baseline never saw adopts its current value as its ceiling (bootstrap, not a violation) ([Ratchet.hs:130](../../../core/app/CE/Verdict/Ratchet.hs#L130), [Ratchet.hs:87-88](../../../core/app/CE/Verdict/Ratchet.hs#L87)).

Tolerance is drawn per run against the *baseline* ceiling, and the new ceiling is `min(v, bv)`, so a drawn edit never raises the committed ceiling: the allowance does not accumulate across runs.

### The discrete ratchet

For discrete violations (clone instances; the roots of unreferenced files, only when a project declares `[deadcode] block`) the baseline is a **set** of violation fingerprints; a new member fails, a removed member shrinks the baseline ([DEVELOPMENT_PLAN.md:210-211](../../DEVELOPMENT_PLAN.md#L210)). The clone members ride the `discrete` set below; the unreferenced files are recorded as the baseline's `deadPoint` = `{files, dead}` (plan v2.35: the entity ids of every file node the graph judged and of the unreferenced ones, the verdict family copying graph/1's `deadNow` into each baseline it writes), and a root the project blocks against that point fails `dead_added` (booklet 06 §10). The implementation is plain set difference both ways over `Data.Set`, with the results returned in ascending order ([Ratchet.hs:121-122](../../../core/app/CE/Verdict/Ratchet.hs#L121), [Ratchet.hs:144-145](../../../core/app/CE/Verdict/Ratchet.hs#L144)):

```
added   = current \ baseline        -- non-empty => fail
removed = baseline \ current        -- informational; drives the shrink
newDisc = current                   -- verbatim, not intersected
```

`newDisc` is the current set verbatim ([Ratchet.hs:131](../../../core/app/CE/Verdict/Ratchet.hs#L131)); the "only shrink" invariant (`new ⊆ old`) is enforced by the *caller's* acceptance gate, not faked inside this function ([Ratchet.hs:94-97](../../../core/app/CE/Verdict/Ratchet.hs#L94)).

**The clone members are T1/T2 blocks.** A member is a block's two sides attributed to their owning units and hashed ([score/mod.rs:492-507](../../../cli/src/score/mod.rs#L492)); the T3 pairs the same run judges (plan v2.30 step 5b-9) are not members — a near-miss pair is a verdict over two whole trees that moves with any edit to either unit, so seating it would fail every committed baseline's fence at the upgrade and again at every reshaping edit. Those pairs charge axis 2 and ride the candidates table instead.

**Member identity (7.0.0).** Since proto 7.0.0 a continuous row's member identity is the §7.2 container anchor — the keys of the units enclosing it, outermost first, hashed, then its order under that chain — rather than `nth`, the occurrence order by start line: the anchor is "the CONTAINER CHAIN instead" ([fourclass/anchor.rs:1-22](../../../cli/src/fourclass/anchor.rs#L1)). Under `nth`, deleting an earlier same-key sibling shifted every survivor's index and the ratchet read one removal plus one addition for a clone nobody touched; under the chain, `impl A { fn add }` and `impl B { fn add }` differ by their impl, and a deletion elsewhere in the file moves no identity. The baseline file therefore stamps `SCHEMA_ID = "ce.baseline/2"` ([baseline.rs:28-34](../../../cli/src/score/baseline.rs#L28)), and a 6.x `/1` file is "refused by name" so that the identity change is a "visible one-time re-establish", never a mass removal plus addition ([baseline.rs:10-15](../../../cli/src/score/baseline.rs#L10)). The index's own `nth` column is untouched — the persisted identity every face prints — while the churn ledger, the join and the seam pricer key on this same anchor since plan v2.30 step 5b item 29 ([anchor.rs:1-10](../../../cli/src/score/anchor.rs#L1)).

**Establish.** With no baseline, `ratchet` returns all five report lists empty — `rOver`, `rDrawn`, `rAdded`, `rRemoved`, `rDropped` — and promotes the current facts wholesale to the new baseline — nothing can fail on the establishing run ([Ratchet.hs:107](../../../core/app/CE/Verdict/Ratchet.hs#L107), [Ratchet.hs:3-6](../../../core/app/CE/Verdict/Ratchet.hs#L3)). The request carries `null` there only when the CLI pinned nothing: `ce check` and the routine `ce baseline` read the committed file once and send it verbatim, `CE_ACCEPT_BASELINE=1` sends `null` on purpose, and `ce trend` sends a pinned *identity* baseline — every ceiling the point's own measurement, its own member set, the run's digest — so its verdict is exact and a failing one is a tripwire that refuses the point rather than caching it ([score/mod.rs:241-245](../../../cli/src/score/mod.rs#L241), [pinned.rs:21-40](../../../cli/src/score/pinned.rs#L21), [trend/mod.rs:203-206](../../../cli/src/trend/mod.rs#L203)).

### Composing the fail bit

ADR-006 makes the ratchet the primary gate for a repository that has a baseline and `--fail-under` a floor underneath it; either alone fails ([DEVELOPMENT_PLAN.md:216-217](../../DEVELOPMENT_PLAN.md#L216)). As built, the fail bit is the disjunction of <!--ce:count:fail_conditions#word-->seven<!--/ce--> **named** conditions ([Faces.hs:25-34](../../../core/app/CE/Verdict/Faces.hs#L25)):

| name | holds when |
|---|---|
| `ratchet_over` | the over list is non-empty |
| `discrete_added` | the added set is non-empty |

### Determinism notes

- The knob digest is a function of the parsed config AND the shipped defaults, never of the file: the serialized config is pruned against the serialized effective default — `null` leaves, leaves equal to the default's, empty objects go; arrays compare whole with the same rules inside their objects, a class's name being a label outside the tree ([canonical.rs:138-161](../../../cli/src/config/canonical.rs#L138)) — and the core's own constants stand in for every absent score / trend / graph knob, READ from the definition package's `limits.score_defaults` — the degraded reply's own echo, `CE.Verdict.Knobs.defaultsEcho` — never held as a Rust copy ([knobs.rs:69-88](../../../cli/src/score/knobs.rs#L69)); the wire gate pins that reading against the echo a knobless request receives. One fixed declaration's literal is frozen in the contract suite, so a serialization change cannot move downstream baselines unannounced.
- Every knob above travels into the pure functions as a parameter; production binds them to the `Cost` constants exactly once, at `scoreBound` ([Score.hs:41-54](../../../core/app/CE/Verdict/Score.hs#L41)) and `ratchetBound` ([Ratchet.hs:44-45](../../../core/app/CE/Verdict/Ratchet.hs#L44)). That is what lets the perturbation batteries move one constant and watch the census move without touching production code ([Cost.hs:1-6](../../../core/app/CE/Verdict/Cost.hs#L1)).
- All arithmetic is `Integer` or `Rational`; the bounded-arithmetic ban is a recorded 2026-08-12 decision ([Cost.hs:12-14](../../../core/app/CE/Verdict/Cost.hs#L12)).
- The baseline crosses the wire verbatim from `ce-baseline.json` and is parsed exactly once, in `respond` ([Verdict.hs:9-11](../../../core/app/CE/Verdict.hs#L9), [Verdict.hs:56](../../../core/app/CE/Verdict.hs#L56)); Rust never interprets it.
